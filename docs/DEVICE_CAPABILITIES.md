# حدود تشغيل الوسائط وخطة إثبات قصيرة

تاريخ التحقق: 2026-11-14. الجهاز المستهدف والمجرّب: LG OLED55CS6LA (موديل 2022)، إصدار SDK المبلغ `11.2.0` والبرنامج الثابت `43.21.94`. أكد المستخدم وجود ساوندبار متصل عبر HDMI eARC، وموديله غير معروف. تجمع هذه الوثيقة بين حدود المواصفات ونتائج الجهاز الفعلية؛ كل نتيجة مذكورة بحدودها ولا تُعمم على صيغة أو حاوية أخرى.

## مسار التشغيل والسرعة

1. **توصية هندسية:** ابدأ بعنصر HTML video واحد ومسار HLS الأصلي للتلفزيون. لا تضف مكتبة تشغيل أو تحويلًا على السيرفر إلى المسار الافتراضي قبل إثبات عطل يحتاجها. الهدف أقل عمل JavaScript وأقل تغييرات في البث، وليس الادعاء أن الأصلي أسرع دائمًا.
2. LG تدعم HTTP/HTTPS وHLS. دعم حاوية TS في جدول الصيغ لا يثبت تلقائيًا توافق كل بث MPEG-TS مستمر؛ ابدأ بمصدر HLS سليم. صيغ DRM تتطلب تكاملها الخاص ولا تُعتبر مدعومة تلقائيًا. [بروتوكولات LG](https://webostv.developer.lge.com/develop/specifications/streaming-protocol-drm)
3. يوجد في HLS قيود على discontinuities وبعض tags والمسارات الصوتية؛ لا تعد بتوافق أي رابط لمجرد انتهائه بـm3u8. احتفظ بالرابط/المانيفست الأصلي دون remux/transcode صامت، خصوصًا لمحتوى Dolby.
4. **قيد مؤكد:** LG لا تدعم رسميًا تشغيل فيديوين معًا داخل التطبيق. لذلك لا dual-video prebuffer ولا تشغيل القناة التالية في الخلفية؛ قد يستهلك اتصال اشتراك ثانٍ ويفشل على جهاز التلفزيون رغم نجاحه على الكمبيوتر. [LG FAQ](https://webostv.developer.lge.com/faq)
5. **توصية هندسية:** واجهة خفيفة، قائمة قنوات مرئية محدودة، وعدم تحميل EPG/صور ضخمة أثناء بدء البث. عند التبديل ألغِ الطلب السابق وأوقف المصدر السابق، وطبّق latest-request-wins حتى لا يعيد callback قديم تشغيل القناة السابقة. لا تبدأ أكثر من مصدر واحد.
6. **توصية هندسية:** افصل زمن استجابة حركة التحديد عن زمن ظهور الفيديو. لا تدع تشغيل القناة ينتظر تحميل EPG أو عرض كل القائمة. حد إعادة الاتصال محدود؛ لا حلقات load/play متواصلة ولا إعادة تشغيل لمجرد كل حدث waiting.
7. API التشغيل الأصلي لا تمنح التطبيق تحكمًا كاملًا في طول المخزن المؤقت؛ لا تعد بزر «صفر تقطيع» أو «buffer صفر». المصدر والشبكة وطول مقاطع HLS ومواضع الإطارات المفتاحية تؤثر في زمن التبديل. البدء الأسرع والمخزن الأكبر مفاضلة تُضبط بالدليل.
8. المتصفح أو المحاكي يصلح لفحص الواجهة ومنطق التحكم فقط. LG تنص على فروق في الأداء والوسائط بين المحاكي والتلفزيون. [قيود المحاكي](https://webostv.developer.lge.com/develop/tools/emulator-introduction)

## اختبار فعلي قليل ومحدد

**قبل التشغيل، بلا اختبار إضافي:** سجّل إصدار webOS/البرنامج الثابت، طريقة الاتصال، وخرج الصوت. يختار المستخدم مصدرين مصرحًا له بهما ويدخل بياناتهما محليًا؛ لا تُحفظ روابط اشتراك أو كلمات مرور في GitHub أو ملفات نتائج المراجعة.

**الجلسة الأولى فقط — نحو 5 دقائق:** شغّل القناة A، ثم بدّل A→B→A، واترك A تعمل 3 دقائق. سجّل زمن أول صورة، زمن كل تبديل، وعدد/مدة توقفات التحميل بعد البدء. استجابة playing وحدها تقدير وليست إثبات وصول أول صورة للشاشة؛ استخدم first-frame callback إن كان متاحًا وسمِّ أي قياس بديل تقديريًا. راقب الصوت أيضًا. نجاح هذه الجلسة يعني smoke test فقط، لا ثباتًا مثبتًا لساعات ولا تفوقًا مثبتًا على TiviMate. لا تستخرج p95 من عينتين.

**جلسة ثانية مشروطة فقط:** بعد نجاح الأساس، عينة رسمية قصيرة موصوفة بـDolby Vision + DD+/Atmos، لمدة 30–60 ثانية. يؤكد المستخدم مؤشر Dolby Vision على التلفزيون وAtmos على مسار الصوت المناسب. ظهور صورة أو canPlayType="probably" لا يثبت كليهما. إذا فشل أحدهما سجّل نوع المصدر والحاوية والمسار/البرنامج الثابت، ثم أصلح السبب المحدد؛ لا تعاود عشرات ملفات العينات.

لا نكرر الجلسة الأولى أو الثانية إلا بعد تغيير يؤثر مباشرة في المسار الذي فشل. فحوص الملفات والمنطق الضرورية تُجرى محليًا دون تشغيل اشتراك المستخدم. لم يتم تنفيذ أي اختبار بث فعلي ضمن هذا البحث.

## مسائل لا تزال مفتوحة

- هل تغير SDK11.2.0 أو البرنامج الثابت43.21.94 منذ القياس السابق، وبلد الجهاز الكامل وموديل الساوندبار المتصل عبر HDMI eARC.
- مصدر المستخدم: HLS أو TS، صيغ الفيديو/الصوت، headers المطلوبة وسياسة الاتصالات المتزامنة.
- Dolby Vision profile/container الفعلي وAtmos carrier في الأفلام المراد تشغيلها.
- تطبيقات webOS قد تختلف عن مشغل USB أو مصدر HDMI حتى على الشاشة نفسها؛ لا تُنقل وعود أحد المسارات إلى الآخر.

مرجع إضافي لتعريف ملفات Dolby Vision وحدود profile/level: [Dolby Professional](https://dolby.my.site.com/professionalsupport/s/article/What-is-Dolby-Vision-Profile).
